Qué pasa cuando el GPS se conecta

Esta es una captura real del diálogo TCP entre un ST‑901 y el servidor:

>>> TCP CONECTADO
EQUIPO  → *HQ,9170004321,HTBT,87#
SERVIDOR ← *HQ,9170004321,HTBT,034456#
EQUIPO  → *HQ,9170004321,V1,034256,A,1024.1200,N,07530.7400,W,23.5,187,250726,FFFFFBFF#
EQUIPO  → *HQ,9170004321,V1,034357,A,1024.3000,N,07530.9000,W,60.0,190,250726,FFFFFBFF#
>>> TCP CERRADO

Puntos importantes de ese diálogo:

  • El equipo abre una conexión TCP y la mantiene abierta enviando tramas.
  • Al heartbeat el servidor sí responde (le confirma que está vivo). Es lo único que responde.
  • A las posiciones no responde nada: las recibe, procesa y guarda. El equipo no espera confirmación.
  • Si pasan 10 minutos sin datos, el servidor cierra la conexión; el equipo vuelve a conectarse solo en su siguiente reporte.

Los dos tipos de mensaje

1. Heartbeat (latido)

*HQ,<id>,HTBT,<batería %>#

Ejemplo:  *HQ,9170004321,HTBT,87#
El servidor lo confirma:  *HQ,9170004321,HTBT,<hora UTC HHMMSS>#

Sirve para dos cosas: mantener viva la conexión y reportar el nivel de batería del equipo. Si baja del 20 % se genera una alerta.

2. Posición (V1)

*HQ,<id>,V1,<hora>,<A|V>,<lat>,<N|S>,<lon>,<E|W>,<vel>,<rumbo>,<fecha>,<estado>#
CampoEjemploQué significa
id9170004321ID del equipo. Es lo que enlaza la trama con la ficha del vehículo.
hora03425603:42:56 en UTC (no hora local).
A | VAA = ubicación válida. V = sin señal GPS confiable (se guarda igual, marcada como inválida).
lat1024.1200,NGrados y minutos → 10.402000. La «S» la haría negativa.
lon07530.7400,W→ −75.512333. La «W» la hace negativa.
vel23.5En nudos. El sistema los pasa a km/h: 23.5 × 1.852 = 43.5 km/h.
rumbo187Grados: 0 = norte, 90 = este, 180 = sur, 270 = oeste.
fecha25072625 de julio de 2026 (día, mes, año).
estadoFFFFFBFF8 dígitos hexadecimales con el estado del motor y las alarmas.

El campo de estado

Son 32 bits donde un 0 significa evento activo (lógica invertida, así funciona el protocolo H02):

BitQué indicaEn el ejemplo FFFFFBFF
0Vibración1 → sin alarma
1Botón SOS1 → sin alarma
2Exceso de velocidad (del equipo)1 → sin alarma
10Ignición / ACC0 → motor encendido
19Corte de energía1 → sin alarma

En el ejemplo, FFFFFBFF significa motor encendido y sin alarmas. El valor crudo siempre se guarda en la base (status_raw), así que si algún equipo usa otra convención se puede reinterpretar sin perder información.

Pendiente de validar con equipo físico El bit de ignición se interpreta según la convención estándar de H02. Cuando instales el primer ST‑901 real, enciende y apaga el vehículo y compara: si el estado del motor sale invertido, se ajusta una línea del parser. Por eso guardamos siempre el valor crudo.

Qué hace el servidor con cada posición

En orden, y diseñado para que el mapa en vivo nunca se caiga aunque falle la base de datos:

  1. 1
    Identifica el equipo

    Busca el unique_id en la tabla de dispositivos. Si no existe, lo crea automáticamente como «ST-901 <id>» — por eso un equipo sin registrar igual aparece en el mapa, solo que sin placa ni conductor.

  2. 2
    Guarda el histórico

    Inserta la posición en la base con su geometría espacial (PostGIS) y la trama original completa, para auditoría.

  3. 3
    Emite en vivo

    Publica el evento position por WebSocket. Es lo que hace que el vehículo se mueva en el mapa al instante. Este paso no espera a la base de datos.

  4. 4
    Evalúa alertas

    Compara con el estado anterior del vehículo: ¿cruzó el límite de velocidad?, ¿arrancó o se detuvo?, ¿entró o salió de una geocerca?, ¿hay alarma de SOS? Solo genera alerta cuando algo cambia.

  5. 5
    Guarda la última posición en Redis

    Para consultas inmediatas sin tocar la base de datos.

Tiempo real (WebSocket)

Socket.IO en el mismo puerto del panel. Requiere el token en el handshake:

const socket = io({ auth: { token: '<token>' } });
socket.on('position', (p) => { /* el vehículo se movió */ });
socket.on('event',    (e) => { /* llegó una alerta */ });

Base de datos

TablaQué guarda
devicesFicha de cada equipo/vehículo: ID, placa, conductor, SIM, APN, límite de velocidad.
positionsCada posición recibida, con geometría espacial y la trama original. Optimizada para series de tiempo (TimescaleDB).
eventsHistorial de alertas generadas.
geofencesZonas vigiladas (círculos y polígonos, con PostGIS).
usersUsuarios del sistema. Las contraseñas se guardan cifradas (bcrypt), nunca en texto plano.

Añadir otros modelos de GPS

Hoy el sistema entiende solo el protocolo H02 (SinoTrack ST‑901 y equipos compatibles). Está construido con un patrón que permite sumar otros sin tocar el resto: para soportar un GT06, Teltonika o Queclink se crea un archivo nuevo en src/protocol-gateway/adapters/ que sepa reconocer e interpretar sus tramas, y se registra en el servidor TCP. El resto del sistema —histórico, alertas, mapa, reportes— funciona igual sin modificaciones.
